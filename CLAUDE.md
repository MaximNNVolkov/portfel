# Проект: веб-приложение для учёта инвестиционного портфеля

Полное техническое задание: @docs/SPEC.md — прочитай его перед началом любой работы.
Макеты ключевых экранов: `docs/mockups.html` (открывается в браузере, интерактивный прототип).

---

## Что это

Веб-приложение для агрегации личного инвестиционного портфеля: банковские вклады, ОФЗ,
корпоративные и муниципальные облигации, акции, ПИФы, денежные средства.

Данные поступают тремя путями: ручной ввод, распознавание скриншотов из банковских
приложений (OCR + LLM), API брокера.

---

## Технологический стек

- **Frontend:** React / Next.js
- **Backend:** Python + FastAPI
- **Database:** PostgreSQL
- **Background jobs:** Celery + Redis
- **Deployment:** Docker Compose (nginx, frontend, backend, postgres, redis, worker, scheduler)
- **Хостинг:** собственный VPS, доступ по HTTPS

## Главные правила разработки

### Объём работ
Разрабатываем **только то, что помечено `[MVP]`** в SPEC.md.
Всё с меткой `[v2]` — не реализуем, но архитектуру проектируем так, чтобы добавить потом
без переработки (PDF-отчёты, админка, уведомления, импорт/экспорт, другие брокеры,
мультипортфельность).

### Интерфейс
- **Никаких модальных окон.** Все содержательные сценарии — отдельные страницы
  с собственным URL и обычной браузерной навигацией «назад». Включая подтверждение
  удаления. (раздел 40.7)
- **Навигация — сайдбар слева**, на мобильном сворачивается в выдвижное меню
  с тем же составом пунктов. Никаких нижних таббаров. (раздел 40.1)
- **Списки без широких таблиц.** Карточный список, разворачивание строки по клику
  (аккордеон, 2-3 строки деталей), пагинация: первые 20 строк + «Загрузить ещё»
  + переключатель количества. Единый паттерн для всех списков. (раздел 40.3)
- **Форма добавления — пошаговый визард:** тип → только обязательные поля →
  подтверждение. Опциональные поля скрыты за «Добавить дополнительные детали». (раздел 40.5)
- **Тёмная тема обязательна.** Зелёный/красный для прибыли/убытка — единообразно
  во всём приложении. Остальной визуальный стиль — на усмотрение разработчика. (раздел 40.6)

### Данные и расчёты
- **Portfolio Engine на бэкенде — единственное место расчётов.** P&L, доходность,
  агрегации не дублируются на фронте. (раздел 10)
- **Отсутствие цены никогда не показывается как 0.** Явная пометка
  «Актуальная цена недоступна» / «Оценка приблизительна». (раздел 7.3)
- **Деградация данных обязательна.** Если брокер недоступен — показываем кэш
  с датой и именем брокера; если кэша нет — показываем доступную часть портфеля
  с явной пометкой, какого брокера не хватает. (раздел 40.2)
- **Курсы валют на MVP — ЦБ РФ.** MOEX ISS только для цен ценных бумаг.
- **OCR: без правки на лету.** Распознанное сохраняется как есть, затем экран-сводка
  «Добавлено со скриншота от дд.мм.гггг» с кнопкой «Редактировать» у каждой записи. (раздел 40.4)

### Безопасность
- Токены брокеров — только в зашифрованном виде, никогда в логах.
- `.env` не коммитим (уже в .gitignore).
- **Хостинг — только в РФ.** Сервер, база и бэкапы физически размещаются на территории
  РФ (решение владельца продукта), это закрывает требование 152-ФЗ из раздела 28.

## Открытые вопросы

Полный список — раздел 38 SPEC.md.

### Решены

- **Источник рыночных данных (раздел 20).** MOEX ISS используется в рамках одного
  собственного сервиса — котировки брать можно. Курсы валют берём у ЦБ РФ (раздел 13).
- **Дедупликация OCR (вопрос №10 раздела 38).** При найденном совпадении система молча
  создаёт новую запись; inline-выбор «обновить или создать новый» не показывается,
  дубликат пользователь правит постфактум на экране-сводке.
- **Лимиты Tinkoff Invest API (раздел 19).** Сценарий использования — один пользователь,
  лимиты не превышаются. Коннектор поддерживает режимы sandbox и production
  (`TINKOFF_API_MODE`).

- **152-ФЗ и размещение данных (вопрос №4 раздела 38).** Хостинг размещается
  на территории РФ, требование раздела 28 выполняется по построению. Выбор
  VPS-провайдера ограничен российской юрисдикцией; база и бэкапы за пределы РФ
  не выносятся (подробности — `docs/DEPLOY.md`).

Критичных открытых вопросов на текущий этап нет.
Если вопрос не решён — спроси, а не принимай решение молча.
