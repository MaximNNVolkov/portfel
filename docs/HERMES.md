# Интеграция с Hermes

[Hermes Agent](https://github.com/NousResearch/hermes-agent) — ИИ-агент владельца,
работает на том же VPS (`~/.hermes`) и общается с ним в Telegram. Интеграция даёт три
вещи:

1. **Вопросы о финансах.** Навык `portfel` отвечает «сколько у меня денег», «какие
   вклады», «что придёт в этом месяце», «есть ли замечания по портфелю».
2. **Полное управление портфелем** (решение владельца 20.10.2026). «Я открыл вклад
   в Сбере на 300 000 под 18,5% до апреля», «купил 10 ОФЗ 26238», «ставка теперь 19%»,
   «купон пришёл», «удали золото», «обнови данные из Т-Инвестиций» — Hermes показывает,
   что сделает, и после подтверждения делает.
3. **Уведомления раз в день.** «Портфель» присылает в Hermes одну сводку в день — только
   о выбранных событиях, по умолчанию о важных. Hermes пересылает её в Telegram.

Все расчёты остаются в «Портфеле» — навык только пересказывает ответы API.

## Как устроено

- **Ключ API** (`pfk_…`) Hermes получает сам по ссылке подключения (см. ниже) или
  его выпускают вручную. В базе хранится только sha256 ключа (`api_keys`). По ключу доступно всё, что
  пользователь делает с портфелем: продукты, операции, выплаты, настройки портфеля,
  синхронизация брокера, обновление цен, скриншоты. Закрыто (403) только управление
  доступом: аккаунт и пароль (`/api/auth/*`), ключи и вебхук (`/api/integrations/*`,
  кроме выбора уведомлений `/api/integrations/hermes/notifications`), токен брокера
  (`POST /api/brokers/tinkoff/connect`). Утёкший ключ отзывается одной кнопкой.
- **Навык** — `integrations/hermes/portfel/`: `SKILL.md` и `scripts/portfel.py`
  (только стандартная библиотека Python). Чтение: `summary`, `products`, `product`,
  `payouts`, `recommendations`, `operations`. Запись: `add-deposit`, `add`, `edit`,
  `delete`, `mark-received`, `add-payout`, `delete-payout`, `add-operation`,
  `delete-operation`, `sync`, `refresh-prices`, `notifications`. У записывающих команд
  есть `--dry-run`; навык требует от Hermes подтверждения владельца перед любой записью.
- **Уведомления** шлёт планировщик (`server/scheduler.ts` → `server/notifications.ts`):
  одна сводка в день в выбранный час (по умолчанию 10:00 по Москве), POST на вебхук
  Hermes. Нет новых событий — нет и сообщения. Тело —
  `{event, text, items, sentAt}`, подпись — Generic V2 Hermes
  (`X-Webhook-Timestamp`, `X-Webhook-Signature-V2` = HMAC-SHA256 от
  `«timestamp.тело»`). Секрет хранится зашифрованным (`TOKEN_ENCRYPTION_KEY`) и
  в интерфейс не возвращается.
- **События** выбираются в «Интеграции → Hermes → Уведомления» (или командой навыка
  `notifications`). По умолчанию включены только важные:

  | Вид | Что сообщает | По умолчанию |
  |---|---|---|
  | `payout_received` | пришли купоны, дивиденды, проценты (за последнюю неделю) | да |
  | `position_closed` | вклад закрыт или облигация погашена — и сколько вернулось | да |
  | `maturity_soon` | за 7 дней до окончания вклада (без автопролонгации) или погашения облигации | да |
  | `broker_error` | синхронизация Т-Инвестиций не прошла | да |
  | `payout_soon` | выплаты в ближайшие 3 дня | нет |
  | `payout_overdue` | выплата за последние 2 недели не отмечена полученной | нет |
  | `weekly_summary` | по понедельникам: стоимость, изменение и выплаты за неделю | нет |

  Каждое событие приходит один раз (`notification_log`). Сводка за день одна
  (`last_digest_on`): событие, появившееся после неё, придёт завтра. Если Hermes не
  ответил, сводка повторится в следующий час, но не позже 22:00.

## Настройка — одной ссылкой

1. В «Портфеле»: «Интеграции → Hermes → Подключить Hermes» → «Скопировать».
2. Отправить скопированное сообщение Hermes в Telegram:
   «Подключись к Портфелю: https://…/api/hermes/connect/…».

Всё. Hermes открывает ссылку, видит инструкцию с одной командой
(`curl -fsSL '…/install.py' | python3 -`) и выполняет её у себя на сервере. Установщик
(`server/hermes-connect.ts`, только стандартная библиотека Python):

- ставит или обновляет навык в `~/.hermes/skills/portfel`;
- придумывает секрет и заводит маршрут `portfel-digest` в
  `~/.hermes/webhook_subscriptions.json` — динамическая подписка Hermes, перезапуск не нужен;
- обменивает ссылку на ключ API (`POST …/claim`) и кладёт адрес и ключ в
  `~/.hermes/skills/portfel/config.json` (права 600);
- «Портфель» сохраняет вебхук `http://host.docker.internal:<порт>/webhooks/portfel-digest`
  и сразу шлёт «Портфель: проверка связи» в Telegram.

Если вебхуки в Hermes были выключены, установщик добавит `WEBHOOK_ENABLED=true`
в `~/.hermes/.env` и попросит один раз перезапустить Hermes; после этого — «Отправить
проверку» в карточке.

Ссылка одноразовая и живёт сутки (`hermes_connect_tokens`, хранится sha256). Повторное
подключение (новая ссылка) обновляет навык, меняет секрет и заменяет ключ прежней
ссылки — так же обновляется навык после изменений в репозитории.

**Сеть.** Backend и планировщик работают в Docker, Hermes — на самом сервере. Контейнеры
видят сервер как `host.docker.internal` (`extra_hosts: host-gateway` в
`docker-compose.yml`; имя меняется переменной `HERMES_WEBHOOK_HOST`). Hermes по
умолчанию слушает порт 8644 на всех адресах, поэтому снаружи порт нужно закрыть
файрволом, оставив доступ сетям Docker (иначе сводка перестанет доходить). С ufw:

```bash
sudo ufw allow from 172.16.0.0/12 to any port 8644 proto tcp   # сети Docker
sudo ufw deny 8644/tcp                                         # всем остальным
```

Проще и надёжнее — закрыть 8644 в файрволе провайдера (он не действует на трафик
внутри сервера).

### Ручная настройка

Если Hermes не может выполнить команду из ссылки — «Интеграции → Hermes → Настроить
вручную»:

1. «Выпустить ключ» и вписать его в `~/.hermes/.env` (`PORTFEL_URL=…`,
   `PORTFEL_API_KEY=pfk_…`), навык скопировать:
   `cp -r ~/portfel/integrations/hermes/portfel ~/.hermes/skills/portfel`.
2. Маршрут вебхука — `hermes webhook subscribe portfel --deliver telegram --deliver-only
   --prompt "{text}"` (печатает секрет) или вручную в `~/.hermes/config.yaml`
   (`platforms.webhook.extra.routes.portfel`: `secret`, `prompt: "{text}"`,
   `deliver: telegram`, `deliver_only: true`); `WEBHOOK_ENABLED=true` в `~/.hermes/.env`.
3. В карточке: адрес `http://host.docker.internal:8644/webhooks/portfel` и тот же секрет.

Ошибки проверки: «не отвечает» — Hermes не запущен, не тот порт или вебхуки выключены;
«отклонил подпись» — секреты различаются; «не найден» — другое имя маршрута.

### Переменные «Портфеля»

Необязательные, для планировщика:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `NOTIFY_INTERVAL_SECONDS` | `3600` | как часто проверять, не пора ли отправить сводку |
| `NOTIFY_TIMEZONE` | `Europe/Moscow` | часовой пояс часа отправки |
| `NOTIFY_TO_HOUR` | `22` | позже этого часа сводка не уходит — переносится на завтра |

Час отправки задаётся в интерфейсе (6:00–21:00), а не переменной.

## Отключение

- Уведомления: «Отключить уведомления» в карточке (вебхук удаляется) или снять галочку
  «Присылать уведомления».
- Доступ навыка: «Отозвать…» у ключа — следующий запрос Hermes получит «ключ не принят».

## Проверки

- `npx tsx server/notifications.test.ts` — события, тексты, выбор событий и часа,
  подпись, проверка адреса.
- `npm test` — смоук: ключ правит и удаляет продукты, пишет операции, меняет
  настройки, но не трогает аккаунт, ключи, вебхук и токен брокера; отзыв ключа;
  выбор уведомлений сохраняется; подписанная проверка вебхука доходит, неверный адрес
  даёт понятную ошибку; ссылка подключения выдаёт инструкцию и установщик, меняется
  на рабочий ключ один раз, повторное подключение отзывает прежний ключ.
