# План тестирования

Как проверяется «Портфель»: автоматические тесты, сквозной обход, субагенты тестер
и критик, ручные проверки владельца и сам цикл «тестирование → план → правки».
Найденное и сделанное ведётся в `docs/IMPROVEMENT_PLAN.md`.

## 1. Автоматические тесты (CI на каждый PR)

Workflow `.github/workflows/ci.yml`, job `checks`: lint, typecheck фронта и сервера,
юнит-тесты, смоук API на Postgres. Job `backend-image` собирает Docker-образ.

Локально:

```
npm run lint
npx tsc -b && npx tsc -p tsconfig.server.json --noEmit
for f in server/*.test.ts; do npx tsx "$f" || echo "FAIL $f"; done
npm test   # server/smoke-test.ts, поднимает API на порту 3091, нужен Postgres
```

### Смоук API `server/smoke-test.ts` (`npm test`)

- регистрация пользователя A
- вход пользователем A
- добавление позиции
- сводка портфеля отражает добавленную позицию
- позиция отдаёт оценку движка, а не сохранённую сумму
- вложено выводится из количества × средней цены и не расходится с ними
- покупка и продажа меняют количество бумаг
- продажа с прибылью даёт реализованный результат и откатывается точно
- параллельные покупки складываются
- проверка параметров и понятные ошибки
- покупка без пополнения не съедает следующий доход
- доходная операция привязывается к инструменту и отвязывается
- дивиденд увеличивает результат, но не «внесено своих»
- выплата «получена» зачисляет деньги, реинвестирование их списывает
- целевая структура: проверка, сохранение, сумма до цели, снятие
- ручная выплата привязывается к инструменту
- удаление второй позиции
- пополнение попадает в свободные деньги и общую стоимость
- купоны облигации прогнозируются без даты купона
- вклад с истёкшим сроком попадает в календарь просроченными выплатами
- полученный возврат тела закрывает вклад без двойного счёта
- погашенная облигация закрывается отметкой погашения
- оценка НДФЛ учитывает купон года, выгрузка — CSV
- импорт выписки: предпросмотр, загрузка, повторная загрузка не задваивает, отмена загрузки, минус по операциям
- доходность за периоды отдаётся списком (§23)
- просроченная выплата отделена от ожидаемых
- просроченная выплата попадает в «Требует внимания», у выплаты есть банк
- повторная загрузка того же скриншота не создаёт новый документ
- изоляция пользователей: чужие позиции, чужая позиция по id, чужая сводка
- удаление аккаунта и недействительность его токена

## 2. Сквозной обход интерфейса

Скрипты в `scripts/qa-cycle/` (как запускать — в их README):

1. `seed.mjs` создаёт пользователя с полным портфелем (8 инструментов всех групп,
   операции, выплаты, 25+ операций для пагинации) и пустого пользователя.
2. `walk.mjs` обходит `/`, `/portfolio`, `/products`, `/attention`, `/transactions`,
   `/payments`, `/analytics`, `/recommendations`, `/integrations`, `/settings`,
   `/reports`, `/import`, формы добавления, `/ocr-summary` и 404 на 390 и 1440 px.
3. На каждой странице: нет горизонтального скролла, нет «NaN / undefined / Invalid Date /
   null / [object Object]», нет ошибок консоли и HTTP 4xx/5xx. Скриншоты затем
   просматриваются вручную.

## 3. Тестер (субагент, сквозные сценарии)

Проходит весь функционал как пользователь, на 1280 и 390 px, и пишет находки
`Т<номер>` с приоритетом P1/P2/P3, шагами, ожидаемым и фактическим:

- регистрация, вход, выход, восстановление пароля, удаление аккаунта;
- пустой портфель и экран первого запуска;
- мастер добавления каждого типа (вклад, облигация, акция, ПИФ, прочее, деньги),
  редактирование, удаление через страницу подтверждения;
- карточка инструмента, операции всех типов (покупка, продажа, пополнение, вывод,
  купон, дивиденд, комиссия, налог), валюты USD и CNY;
- выплаты: календарь по дням, месяцам и годам, фильтры, отметка полученной и отмена;
- «Требует внимания», аналитика (структура, доходность по периодам, налоги и CSV),
  рекомендации, целевая структура и ребалансировка;
- импорт выписки: CSV (UTF-8, Windows-1251, UTF-16), Excel, большие файлы, повторная
  загрузка, отмена загрузки;
- OCR-загрузка скриншота, Т-Инвестиции без токена (деградация), PWA (манифест, иконки);
- сверка цифр между главной, категорией, карточкой и аналитикой; нет нуля вместо
  «цена недоступна», нет модальных окон, английских ошибок и 500.

## 4. Критик (субагент, логика с точки зрения клиента)

Читает ТЗ и код движка и смотрит глазами частного инвестора и финансиста,
находки — `К<номер>` со ссылкой на код и предложением исправления:

- P&L, доходность, НКД, купоны и погашения (амортизация, оферта), проценты по вкладам
  (капитализация, выплата в конце срока, пролонгация), валютная переоценка;
- налоги: НДФЛ 13/15%, необлагаемый лимит по вкладам, продажи и погашения;
- двойной счёт (выплата, позиция, деньги), снимки истории, свободные деньги;
- ложные срабатывания рекомендаций, шум и срочность в «Требует внимания»;
- импорт выписки: дубликаты, знаки, статусы;
- граничные случаи: частичная продажа, продажа в минус, одна бумага на нескольких
  счетах, валюта без курса, вклад задним числом, облигация без даты купона.

Путь клиента, по которому оценивается логика: портфель → категории → инструменты →
что требует внимания → в каком банке что лежит.

## 5. Ручные проверки, которые ждут владельца

- Safari на macOS и iOS: главная, инструменты, форма добавления (§37 п. 16).
- Настоящий read-only токен Т-Инвестиций на стенде: подключение и синхронизация
  (§37 п. 7–8).
- Курсы ЦБ на стенде. Из облачной среды cbr.ru отвечал то 403, то 200 (30.09 курс
  загрузился), поэтому окончательно пересчёт валютных позиций проверяется на стенде.
- Образцы выписок и брокерских отчётов Сбера, ВТБ и Альфы (можно обезличенные) —
  для точных форматов импорта.
- Восстановление из резервной копии (§37 п. 17) — процедура в `docs/DEPLOY.md`.

## 6. Цикл «тестирование → план → правки»

Выполнялся ежедневной рутиной (сейчас отключена по решению владельца 29.09.2026).
Шаги одного круга:

1. Обновить `main`, поднять локальный Postgres (`service postgresql start`, `.env`
   с `DATABASE_URL` portfel:portfel), `npm ci`, миграции применяются при старте API.
2. Прогнать раздел 1 целиком: `npm test`, юнит-тесты, typecheck, lint.
3. Запустить API (`API_RATE_LIMIT=100000`) и Vite, прогнать раздел 2 на 390 и 1440 px.
4. Параллельно запустить тестера (раздел 3) и критика (раздел 4).
5. Их находки внести в `docs/IMPROVEMENT_PLAN.md` новым разделом «Прогон <дата>»,
   отметить сделанное.
6. Реализовать верхние пункты небольшими PR с ветки `claude/test-and-improve-7ldjoq`,
   перед PR — все проверки раздела 1; влить при зелёном CI.
7. Итог круга — одно короткое сообщение владельцу: что исправлено, что нужно от него
   для выкладки (миграции, конфиг nginx).
