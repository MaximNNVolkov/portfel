# portfel

Веб-приложение для учёта и анализа личного инвестиционного портфеля.

Объединяет в единую картину банковские вклады, ОФЗ, корпоративные и муниципальные
облигации, акции, ПИФы и денежные средства из разных банков и брокеров — чтобы
не сводить всё вручную из нескольких приложений.

## Что уже работает

- Регистрация и вход по email + паролю, сессии живут в базе (переживают перезапуск сервера)
- Портфель: общая стоимость, вложено, P&L, доходность, структура по группам инструментов, график
- Пустой портфель (новый пользователь) показывает экран-приглашение с тремя способами
  добавить первый актив, а не сломанные проценты
- Инструменты: добавление вручную, редактирование, удаление — с отдельной страницей
  подтверждения перед удалением
- Добавление продукта по скриншоту: локальное распознавание текста (без внешних LLM-сервисов
  и без интернета) выполняется асинхронно в фоновом процессе со статусом обработки; результат
  сохраняется как есть, правки — постфактум на отдельной странице
- Операции (покупки/продажи/пополнения/выплаты) и календарь выплат, включая прогноз процентов
  по вкладам и купонов/погашений по облигациям
- Базовая аналитика и аналитические уведомления (концентрация, погашения, просадки, разрывы в выплатах)
- Подключение Т-Инвестиций: счета, позиции, операции, купоны и дивиденды синхронизируются
  с брокером — по кнопке и автоматически раз в сутки
- Курсы валют — ЦБ РФ, текущие цены акций, фондов и облигаций — MOEX ISS
- Ежедневные снимки портфеля (история стоимости) и ежедневный бэкап базы
- Тёмная тема: светлая / тёмная / как в системе, переключается в настройках
- Восстановление пароля по email
- Вся навигация — обычные страницы с собственным URL, работает кнопка «назад» браузера

Каждый пользователь видит только свой портфель — данные разных аккаунтов не пересекаются.

## Известные ограничения

- Поддерживается один брокер — Т-Инвестиции; остальные брокеры запланированы на v2
- Распознавание скриншотов — только OCR (tesseract.js), LLM-шага из §18 нет
- Доходность — простая формула без XIRR, исторические курсы валют не используются (v2)
- Документация API (OpenAPI) ещё не опубликована — пункт 6.8 в `docs/.NEXT_STEPS.md`

## Технологический стек

Стек отличается от первоначального варианта ТЗ (Next.js, FastAPI, Celery + Redis) —
решено продолжать на TypeScript, см. `docs/SPEC.md` §32 и `docs/CLAUDE.md`:

- **Frontend:** Vite + React 19 + React Router (`src/`)
- **Backend:** Express 5 + TypeScript (`server/index.ts`): в разработке и на стенде — через `tsx`,
  в production-образе — скомпилированный JS (`npm run build:server`)
- **Database:** PostgreSQL 16, миграции — SQL-файлы в `db/migrations/`
- **Фоновые задачи:** отдельный процесс-планировщик `server/scheduler.ts` (без Celery/Redis):
  синхронизация брокера, цены MOEX, прогноз выплат, ежедневные снимки, очередь OCR
- **OCR:** tesseract.js — распознавание текста со скриншота локально, без внешних API
- **Деплой:** Docker Compose — nginx (раздаёт собранный фронт и проксирует `/api/`),
  backend, scheduler, postgres, backup, certbot (см. `docs/DEPLOY.md`)

## Как запустить

Нужны Node.js 20+ и Docker.

```bash
# 1. Поднять базу данных для разработки
docker run -d --name portfel-postgres-dev -p 5432:5432 \
  -e POSTGRES_DB=portfel -e POSTGRES_USER=portfel -e POSTGRES_PASSWORD=portfel \
  postgres:16-alpine

# 2. Установить зависимости
npm install

# 3. Запустить backend, планировщик и frontend одновременно
npm run dev:full
```

`docker-compose.yml` описывает боевой стенд (nginx с HTTPS, секреты из `.env`, порт базы
наружу не публикуется), поэтому для локальной разработки база поднимается отдельно.

Приложение откроется на [http://localhost:5173](http://localhost:5173). Backend слушает
`http://localhost:3001`. При первом запуске — зарегистрировать аккаунт (email + пароль) прямо
на странице входа.

По умолчанию backend подключается к `postgresql://portfel:portfel@localhost:5432/portfel`
(база из шага 1). Чтобы использовать другую базу или порт, задайте переменные
окружения `DATABASE_URL` и `PORT` перед запуском.

Отдельные команды, если нужно запускать сервисы порознь:

```bash
npm run api        # только backend, http://localhost:3001
npm run scheduler  # только фоновые задачи (без него скриншоты не распознаются)
npm run dev        # только frontend, http://localhost:5173
npm test           # smoke-тест backend
```

## Миграции базы данных

Схема базы описана SQL-файлами в `db/migrations/` — каждый с числовым префиксом
(`001_init_legacy.sql`). Применённые миграции записываются в таблицу `schema_migrations`,
так что повторный запуск ничего не ломает: выполняются только новые файлы, каждый
в отдельной транзакции.

Миграции применяются автоматически при старте backend (`npm run api`). Применить их
отдельно, не поднимая сервер:

```bash
npm run db:migrate
```

Новая миграция — это новый файл `db/migrations/<номер>_<имя>.sql` со следующим по порядку
номером. Уже применённые файлы не редактируем: изменения оформляем отдельной миграцией.
