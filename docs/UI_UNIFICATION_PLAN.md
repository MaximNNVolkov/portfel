# Единый вид экранов — план работ

Продолжение `docs/CLIENT_FLOW_PLAN.md`. Владелец выбрал для карточки инструмента вариант A
из `docs/redesign/instrument-card-variants.html` («Итог и прогноз») и попросил привести
к тому же виду все экраны. Здесь — принятые решения, общие правила и очередь работ
по экранам.

## 1. Решения владельца

1. **Карточка инструмента — вариант A** с правками:
   - кнопки «Получена» в карточке нет;
   - история операций — на отдельной вкладке;
   - выплаты — отдельной вкладкой, лентой по образцу варианта C («Жизнь инструмента»).
     Вместо заголовков «Было» и «Будет» прошлое выделено цветом: прошедшее бледнее.
2. **Купоны, проценты и дивиденды с прошедшей датой считаются полученными.** Отмечать их
   вручную не нужно: сервер сам переводит такую выплату в «получено» и заводит операцию,
   деньги попадают в свободные. Ручной отметки по-прежнему ждут только возврат тела
   вклада и погашение номинала: они закрывают позицию, а фактическую дату возврата
   знает только пользователь. Брокерские выплаты не трогаем — их приносит синхронизация.
3. **Прогноз поступлений считается на бэкенде** (§10: Portfolio Engine — единственное место
   расчётов). Он нужен на многих экранах: карточка, «Выплаты», «Портфель».
4. **Параметры инструмента — строкой** «факт · факт», как в строке списка, а не чипами.
5. **Доходности к погашению пока нет:** её нужно сначала посчитать на бэкенде. Отложено,
   см. §4.

## 2. Общие правила для всех экранов

- **Шапка экрана с суммой** — как на «Портфеле»: подпись мелкими заглавными, крупная
  сумма, под ней строка результата: плашка «+₽ …» и процент с подписью. Ниже, если
  нужно, мелкая строка фактов через « · ». Отдельные сетки «Стоимость / Вложено /
  Доход / Доля» не используются там, где хватает одной строки.
- **Нули не показываются.** «Получено ₽ 0», «Доход +₽ 0» не выводятся: строка исчезает
  или заменяется словами («выплат пока не было»).
- **Оценка помечается у самой суммы:** «≈ по цене покупки», «≈ оценка приблизительна» (§7.3).
- **Строка списка одна для всех экранов:** точка цвета типа, название, сумма справа; ниже
  мелко «банк · событие» и результат в процентах. Ближайшее событие в карточке и
  «Требует внимания» — та же строка.
- **Действия.** Залитая оранжевая кнопка — только «Добавить». Действия в строках —
  кнопки с рамкой. Служебные действия экрана («＋ Операция», «＋ Выплата»,
  «Редактировать») — под раскрытием «Ещё действия и детали». «Удалить» — текстом справа,
  а не кнопкой в ряду.
- **Одинаковые подписи:** «Отметить полученной» (не «Получена»), «← Назад» на всех
  внутренних страницах (в карточку попадают из разных мест).
- **Переключатели вида и вкладки** — один компонент `.view-mode-switch`, как «Дни /
  Месяцы / Годы» в «Выплатах». Выбранная вкладка хранится в адресе (`?tab=`), чтобы
  «назад» возвращал туда же (§40.7).
- **Ширина на десктопе:** у страниц с одной колонкой содержимое ограничено (~760 px),
  а не растянуто на всю ширину.
- **Ленты по времени** (выплаты, история): прошедшее бледнее, будущее в полный цвет,
  «Сегодня» — плашка с текущей суммой. Повторяющиеся записи сворачиваются в
  «ещё N выплат» и раскрываются на месте.

## 3. Очередь работ

Признак готовности каждого пункта: `npx tsc -b`, `npx tsc -p tsconfig.server.json`,
`npm run lint`, юнит-тесты `server/*.test.ts` и `npm test` чистые; экран помещается
в 390 px без горизонтальной прокрутки.

### Волна 1 — карточка инструмента и прогноз (сделано)

- [x] Бэкенд: купоны, проценты и дивиденды с прошедшей датой переводятся в «получено»
      с операцией (`settleDuePayouts` в `server/daily-tasks.ts`). Перевод выполняется
      при пересчёте прогноза, раз в сутки планировщиком и перед чтением выплат,
      сводки, позиций, операций и «Требует внимания». Ручная выплата дохода с прошедшей
      датой сразу сохраняется полученной.
- [x] Бэкенд: в прогноз ручной облигации попадают купоны с даты покупки. Прошедшие
      становятся полученными; если пользователь уже внёс такой купон сам (±20 дней),
      второй не заводится.
- [x] Бэкенд: прогноз поступлений по инструменту `server/payout-outlook.ts` — получено,
      ещё придёт, вернётся телом, просроченный возврат, ближайшая выплата. Отдаётся
      полем `outlook` у каждой позиции (`/api/positions`).
- [x] Карточка инструмента: шапка как у «Портфеля», строка фактов, блок срока
      с прогнозом, ближайшее событие без кнопки, вкладки «Выплаты» (лента) и «История»,
      служебное под «Ещё действия и детали», ширина 760 px.

### Волна 2 — прогноз поступлений на «Выплатах» и «Портфеле» (сделано)

- [x] `GET /api/payouts/outlook`: плитки трёх ближайших месяцев и 12 месяцев вперёд,
      сетка из 12 дней, месяцев или лет и итог окна (`payoutPeriods` в
      `server/payout-outlook.ts`). Фильтры экрана (тип, инструмент, банк) применяет сервер.
- [x] «Выплаты»: плитки и сетка берут суммы из нового эндпоинта. Локальное сложение
      осталось только офлайн-фолбэком без бэкенда — как `localSummary`.
- [x] Подписи: прошедший доход больше не ждёт отметки, поэтому «не отмечено полученным»
      заменено на «Ждут отметки» — это только возврат тела и погашение. Кнопка везде
      «Отметить полученной».
- [x] Формы добавления и правки выплаты: у купона, процентов и дивидендов с прошедшей
      датой выбора статуса нет — подпись «сохранится полученной».
- [x] «Портфель»: «Получено выплат» и новая плитка «Ещё придёт» считаются той же функцией
      (`payoutSums`), что и прогноз; SQL-сумма `sumPayouts` удалена. Нули заменены словами.

### Волна 3 — шапки и строки списков (сделано)

- [x] Категория (`/products?group=`): шапка как у «Портфеля» и карточки — крупная сумма,
      строка результата (нулевой доход не выводится), строкой фактов «вложено · доля
      портфеля · число инструментов». Сетка «Стоимость / Вложено / Доход / Доля» убрана.
- [x] Срез по банку (`/products?bank=`): та же шапка «Хранится в банке».
- [x] Строки инструментов: ближайшая выплата берётся из прогноза бэкенда (`outlook.next`),
      фронтовый `nearestPayoutMap` удалён; сортировка «по ближайшей выплате» — по нему же.
- [x] «Операции»: фильтр по инструменту из адреса `?position=` (и выбором в фильтрах), с
      «← Назад»; на вкладке «История» карточки — «Все операции по инструменту».
- [x] «Требует внимания»: подписи действий по §2 («Отметить полученной»), неотмеченный
      возврат — «ждут отметки».

## 4. Отложено

- **Доходность к погашению** облигации — нужен расчёт в Portfolio Engine (цена, НКД,
  купонный график). Когда появится, она займёт место в строке фактов карточки.
- **Расклад дохода** по составляющим (рост цены, купоны, комиссии) — вариант B макета.
  Можно добавить в карточку, когда бэкенд будет отдавать составляющие по инструменту.
