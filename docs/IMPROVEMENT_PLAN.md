# План доработок по итогам сквозного тестирования

Живой документ цикла «тестирование → план → правки». Цикл повторяется ежедневно:
каждый прогон дописывает раздел «Прогон», отмечает сделанное и добавляет найденное.
Приоритеты: **P1** — неверные цифры или нарушение правил ТЗ, **P2** — заметные
неудобства, **P3** — косметика.

## Как тестируется

- `npm test` (смоук API на локальном Postgres), юнит-тесты `server/*.test.ts`,
  typecheck фронта и сервера, `npm run lint`.
- Headless Chromium: все вкладки и формы (`/`, `/products`, `/attention`,
  `/transactions`, `/payments`, `/analytics`, `/recommendations`, `/integrations`,
  `/settings`, `/reports`, `/import`, формы добавления, 404) на 390 и 1440 px,
  для пользователя с данными (8 инструментов всех групп, операции, выплаты, 25+
  операций для пагинации) и для пустого портфеля. Проверяются горизонтальный
  скролл, ошибки консоли и HTTP, «NaN/undefined/Invalid Date» в тексте, затем
  скриншоты просматриваются вручную.

## Прогон 2026-09-29

Автопроверки: всё зелёное, горизонтального скролла и ошибок консоли нет ни на одном
экране. Найдено при ручном просмотре:

### P1

1. **Покупка/продажа не меняет количество бумаг.** Операция «Покупка» через
   «Новая операция» увеличивала «вложено», но не количество; у позиции, которая
   оценивается как количество × цена, докупка выглядела убытком на всю сумму.
   В форме не было и даты — любая операция проводилась сегодняшним числом.
   → Операция хранит количество и цену (если не указаны — количество выводится из
   цены позиции), продажа сверх остатка отклоняется, в форме появились поля
   «Количество», «Цена за штуку» и «Дата». **Сделано** (PR #14).
2. **Нет курса валюты → «₽ 0».** В «Аналитике» строки «USD» (по валютам) и
   «Наличные USD» (по инструментам) показывают «₽ 0 · 0% портфеля», хотя цена
   недоступна (§7.3: отсутствие цены никогда не показывается как 0). Нужна та же
   пометка «Оценка недоступна», что в списке инструментов. **Сделано.**
3. **«Разрыв в выплатах» считает возврат тела как доход.** Средний доход в
   рекомендации («в среднем портфель приносит 280 730 ₽ в месяц») включает возврат
   вклада и погашение облигации; из-за этого средняя завышена и почти каждый
   месяц выглядит «разрывом». Возврат тела и погашение номинала в средний доход
   включаться не должны. **Сделано.**

### P2

4. **Лимит API 300 запросов за 15 минут на IP.** Одна загрузка приложения — около
   9 запросов, то есть ~30 обновлений страницы за 15 минут, после чего все экраны
   получают 429. Для семьи за одним NAT ещё меньше. Сделать лимит настраиваемым
   (`API_RATE_LIMIT`) и поднять значение по умолчанию. **Сделано** (1500).
5. **Склонение «для 1 инструмент(ов)»** в баннерах о недоступной цене на главной.
   Исправляется в PR #13 (тред «Пересмотр логики портфеля»).
6. **Проценты с точкой** в текстах рекомендаций («снизилась на 14.7%»), везде
   остальное — с запятой. **Сделано.**
7. **Полученные выплаты без типа.** В «Выплатах» у полученных строк подпись только
   «получено», у ожидаемых — «Купон · Т-Инвестиции»; нужен тип и счёт и у тех, и у других. **Сделано.**
   Причина глубже: купон или дивиденд, проведённый операцией, нельзя было привязать
   к бумаге, и он не попадал в её карточку (§9). Теперь у операций «Купон»,
   «Дивиденды», «Проценты» есть необязательное поле «Инструмент». **Сделано.**
8. **Денежный остаток в рублях не виден в «Инструментах».** Категория «Деньги» на
   главной показывает ₽ 42 650, а в списке инструментов в группе «Деньги» только
   валютная позиция.

### P3

9. На ноутбуке 1440×900 кнопка «Выйти» внизу сайдбара уходит за край (сайдбар
   прокручивается, но это неочевидно).
10. Индикатор «Синхронизировано с API» в шапке при отсутствии подключённого брокера
    читается как статус брокера.
11. API принимает периодичность выплат по вкладу только по-русски («ежемесячно»);
    `monthly` молча превращается в выплату в конце срока.

## Новые возможности (одобрены владельцем 2026-09-29)

По SPEC это задел v2, но владелец включил их в текущий план. Порядок — от простого
к сложному; Telegram-уведомления пока не делаем (решение владельца).

1. **Установка на телефон (PWA)**: манифест, иконки, service worker, который кэширует
   только оболочку приложения (данные портфеля на устройстве не сохраняются).
   **Сделано.**
2. **Целевая структура и ребалансировка**: пользователь задаёт целевые доли по
   категориям в настройках; на главной и в «Аналитике» — отклонение от цели и
   подсказка, сколько докупить/сколько лишнего, в пункте «Требует внимания» при
   отклонении больше порога. **Сделано.**
3. **Налоги**: оценка НДФЛ по полученным купонам, дивидендам и процентам по вкладам
   за год (13%/15%, необлагаемый лимит процентов по вкладам = 1 млн ₽ × максимальная
   ключевая ставка года), выгрузка CSV с разбивкой по источникам для 3-НДФЛ.
   Оценка, а не расчёт налогового агента: брокер удерживает налог сам, это видно
   в пометках.
4. **Импорт выписок Сбера, ВТБ, Альфы из файлов**: разбор брокерских отчётов и
   выписок (XLSX/CSV) в операции и позиции, экран-сводка как у OCR (§40.4).
   Нужны реальные образцы файлов — без них делаем импорт универсального CSV
   с сопоставлением колонок, а форматы банков добавляем по образцам.

## Нужно от владельца

Без владельца не проверить, работа по плану из-за этого не стоит:

- Safari (macOS/iOS) — пройти главную, инструменты и форму добавления (§37 п. 16).
- Настоящий read-only токен Т-Инвестиций на стенде — подключение и синхронизация
  (§37 п. 7-8).
- Курсы ЦБ: из тестовой среды `cbr.ru` отвечает 403, поэтому пересчёт валютных
  позиций здесь не проверяется; на стенде убедиться, что USD-позиции получают цену.
- Образцы выписок/брокерских отчётов Сбера, ВТБ и Альфы (можно обезличенные) —
  для импорта файлов.
- Деплой на стенд после слияния PR.
