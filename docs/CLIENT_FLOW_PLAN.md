# Редизайн по сценарию клиента: портфель → категории → инструменты → что требует внимания

Статус: **одобрен владельцем 29.09.2026, волны A-F выполнены** (скриншоты —
`docs/redesign/client-flow/`). Предыдущий план (`REDESIGN_PLAN.md`, волны 1-5) выровнял внешний
вид списков, но не трогал содержание экранов. Этот план — про содержание и порядок
экранов.

## 1. Сценарий клиента (как владелец пользуется продуктом)

1. **Вижу портфель целиком** — сколько всего, сколько заработал.
2. **Вижу категории**, из которых он состоит (вклады, облигации, акции…).
3. **Открываю категорию** и вижу инструменты в ней.
4. **Понимаю, что требует внимания**: скорая выплата, которую надо реинвестировать,
   заканчивающийся вклад, погашение, просроченная неотмеченная выплата, нет цены.
5. **Вижу, где что хранится**: в каком банке / у какого брокера лежит каждый
   инструмент и сколько денег в каждом банке.

Каждый экран отвечает на один из этих вопросов. Всё, что не помогает ответить,
уходит глубже (в карточку, в «подробнее») или убирается.

## 2. Критический разбор текущих экранов

### 2.1. Главный экран «Портфель»

- Приветствие, дата и «Вот как чувствует себя ваш капитал» занимают первый экран
  на мобильном и не несут данных.
- Кнопки периода графика «1Г / Всё время» — декоративные, обработчиков нет
  (`Dashboard`, `.periods`). Либо сделать рабочими, либо убрать.
- «Кратко о портфеле» повторяет итог сверху (инвестировано, выплаты) отдельной
  карточкой; «Подробнее о портфеле» и «Все инструменты» ведут в одно место.
- Категории в структуре **не кликабельны**: шаг 2 → 3 сценария невозможен, клиент
  попадает в общий список всех инструментов и фильтрует его вручную.
- Подпись «1 продукт(а)» — канцелярит; доля портфеля показана дважды (в процентах
  с запятой и округлённая).
- Нет блока «Требует внимания» (шаг 4): сигналы разбросаны по «Выплатам»
  (просрочено), «Рекомендациям» (погашение, просадка) и баннерам.
- Нет ответа «где что хранится» (шаг 5): разрез по банкам есть только в «Аналитике»
  (`byBank`, `byBroker`), на главной — нет.

### 2.2. Список инструментов и строка инструмента

- Банк/брокер спрятан в раскрытие строки, хотя для клиента это ключевой атрибут.
- Раскрытие дублирует карточку инструмента (сумма покупки, количество × цена,
  дата покупки) — двойная работа: раскрыть, потом всё равно «Подробнее →».
- Фильтр «Все типы» дублирует категории, которых на этом экране не видно.
- Нет итогов по категории над списком, хотя §8 ТЗ их требует.

### 2.3. Карточка инструмента

- Плоский список из ~20 строк одного веса: «Тикер —», «ISIN —», «Валюта RUB»,
  «Источник данных» стоят в одном ряду с главным — стоимостью и результатом.
- Одинаковый набор полей для вклада, облигации и акции: у вклада «Текущая цена»
  и «Средняя цена» бессмысленны, у акции — «Окончание вклада».
- «Нереализованный P&L» — жаргон; клиенту понятнее «Доход сейчас».
- Нет ответа «что дальше» — ближайшая выплата/погашение видны только внутри
  «Истории выплат» внизу страницы.
- История операций и история выплат — два отдельных старых списка (`list-card`),
  хотя для клиента это одна лента событий по инструменту.

### 2.4. Операции

- Название операции часто совпадает с типом («Покупка» / «Покупка»), в раскрытии
  повторяются дата (уже в строке) и валюта (почти всегда RUB).
- Фолбэк «Портфель Основной» вместо «без инструмента» сбивает с толку.
- Не видно, в каком банке/у какого брокера прошла операция.

### 2.5. Выплаты

- Строка: «Купон ОФЗ 26238» и ниже «Купон» — тип повторён дважды.
- Раскрытие показывает Статус, Дату, Валюту — всё уже есть в строке. Реально
  полезное (где получу деньги, что с ними делать) — отсутствует.
- На мобильном 4 поля фильтров (тип, инструмент, с, по) занимают первый экран до
  первой выплаты.
- Пояснение у блока «Просрочено» — три строки текста над каждым списком.
- Нет действия «реинвестировать» — выплата заканчивается отметкой «получено».

## 3. Что есть в данных (проверено по коду)

- **Банк/брокер хранится.** Позиция привязана к счёту `portfolio.accounts`, у счёта
  поле `provider` (название банка или брокера). В API позиций оно отдаётся как
  `institution` (`server/positions.ts:195`). Для ручных записей без банка —
  «Ручной ввод».
- У выплат и операций есть `accountId`, то есть банк можно показать и там —
  достаточно отдавать `institution` в ответах `/payouts` и `/transactions`
  (или сопоставлять по позициям на фронте без расчётов).
- Разрезы по банкам и брокерам уже считает бэкенд (`byBank`, `byBroker`
  в `GET /api/portfolio/structure`), но раздельно и без счетов типа `other`
  (ручной ввод без банка). Для «Где хранится» нужен один разрез по `provider`
  по всем счетам — небольшая правка там же.
- Сигналы для «Требует внимания» уже есть по отдельности: просроченные выплаты
  (`overdue`), ближайшие выплаты, правила рекомендаций `maturity`, `drawdown`,
  `concentration`, `payout_gap`, позиции без цены, `forecastNote`, ошибка
  синхронизации брокера. Общей ленты нет.
- Понятия «реинвестировать» в модели нет. Для MVP это напоминание плюс переход
  к добавлению покупки с подставленной суммой и банком — без новой сущности.

Схему БД менять не нужно.

## 4. Целевая структура экранов

Сайдбар остаётся по §40.1 (состав пунктов тот же). Меняется содержание страниц
и связи между ними.

### 4.1. «Портфель» (`/portfolio`)

Сверху вниз:

1. **Итог**: общая стоимость, доход за всё время (₽ и %), пометки неполноты
   данных (§40.2). Без приветствия. Строка ниже мелко: «Вложено · Получено
   выплат · Свободные деньги».
2. **Требует внимания** — до 3-5 карточек, самые срочные сверху, у каждой одно
   действие. Ссылка «Все (N)» → `/attention`. Если нечего — одна строка
   «Всё в порядке».
3. **Категории** — строки с точкой цвета, суммой, долей и доходом; строка ведёт
   в категорию. Кольцевая диаграмма остаётся компактной слева на десктопе.
4. **Где хранится** — строки по банкам/брокерам: название, сумма, доля, число
   инструментов; строка ведёт в список инструментов этого банка.
5. **График стоимости** — внизу, с рабочими периодами или без переключателя.

«Кратко о портфеле» и «Ближайшие выплаты» как отдельные карточки убираются:
цифры переходят в итог, выплаты — в «Требует внимания».

### 4.2. Категория (`/products?group=<тип>`, та же страница «Инструменты»)

- Шапка категории: сумма, вложено, доход, доля в портфеле (§8).
- Переключатель «Все банки / <банк>…» вместо фильтра по типу.
- Строка инструмента: название + стоимость; ниже мелко **банк · ближайшее событие**
  («ВТБ · купон 7 окт, 18 450 ₽») + доход в %.
- Раскрытие строки убирается: тап по строке сразу открывает карточку. Это
  отступление от §40.3 (аккордеон) — см. вопрос 2.
- «Инструменты» без параметра = все категории подряд с подзаголовками.

### 4.3. Карточка инструмента (`/products/:id`)

1. **Шапка**: название, тип, банк/брокер, стоимость, доход (₽ и %).
2. **Что дальше**: ближайшая выплата или погашение/окончание вклада с суммой и
   действием («Отметить полученной», «Реинвестировать»).
3. **Главные параметры по типу**:
   - вклад — ставка, дата окончания, капитализация, выплата процентов;
   - облигация — купон, дата погашения/оферты, количество, НКД;
   - акция/фонд — количество, средняя и текущая цена (с датой котировки).
4. **История** — одна лента операций и выплат по дате.
5. **Детали** (свёрнуто): тикер, ISIN, валюта, источник данных, дата покупки.
   Пустые поля не показываются вовсе, а не «—».
6. Редактировать / удалить — внизу.

### 4.4. «Требует внимания» (`/attention`, новая страница)

Одна лента сигналов, каждый с датой, суммой, банком и одним действием:

| Сигнал | Действие |
|---|---|
| Выплата в ближайшие 14 дней | «Реинвестировать» (после получения) |
| Выплата прошла, не отмечена | «Отметить полученной» |
| Вклад заканчивается / облигация погашается в ближайшие 30 дней | «Открыть» / «Реинвестировать» |
| Нет актуальной цены | «Обновить цены» |
| Не хватает данных для прогноза выплат | «Заполнить» |
| Брокер не синхронизирован | «Повторить» |
| Концентрация, просадка, разрыв в выплатах | «Открыть» |

Лента собирается **на бэкенде** (Portfolio Engine — единственное место расчётов),
новый эндпоинт `GET /api/attention`. «Рекомендации» остаются отдельным разделом
по §6, но их сигналы тоже попадают в ленту.

### 4.5. «Выплаты» (`/payments`)

- Строка: инструмент + сумма; ниже мелко **банк · дата**, пометки только
  когда они что-то меняют (прогноз — приглушённо, просрочено — красным).
  Тип выплаты — цветом точки и в подписи только если он не очевиден из названия.
- Раскрытие вместо «Статус / Дата / Валюта»: банк, куда придут деньги, и
  действия «Отметить полученной» / «Реинвестировать» / «Редактировать».
- Фильтры сворачиваются в одну кнопку «Фильтры» на мобильном; добавляется фильтр
  по банку.
- Пояснение у «Просрочено» — одна строка.

### 4.6. «Операции» (`/transactions`)

- Строка: инструмент (или «Без инструмента») + сумма со знаком; ниже мелко
  **тип · банк · дата**. Если название совпадает с типом — не повторяем.
- В раскрытии только то, чего нет в строке: количество × цена, комиссия, налог,
  источник; и действия.
- Фильтры по банку и типу.

## 6. Решения по умолчанию (владелец не возражал)

1. **«Реинвестировать» — что это делает?** По умолчанию: напоминание в «Требует
   внимания» и переход на форму покупки с подставленной суммой и банком. Учёт
   «денег к реинвестированию» отдельной сущностью — не делаем.
2. **Раскрытие строки в списке инструментов.** §40.3 требует аккордеон. Предлагаю
   для инструментов тап сразу открывать карточку (раскрытие дублирует её), а
   аккордеон оставить для выплат и операций, где отдельной страницы нет.
   По умолчанию — так.
3. **Горизонт «скоро».** По умолчанию: выплаты — 14 дней, окончание вклада и
   погашение — 30 дней. Настраивается в «Настройках» позже.
4. **Банк и брокер в «Где хранится» — одним списком?** По умолчанию да: для
   клиента это одинаково «место, где лежат деньги».
